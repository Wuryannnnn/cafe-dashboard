# 支付接入说明（微信 / 支付宝）

> 现状：项目**尚未接入真实支付**。所有商户凭据是 `test`/空占位，调 `/pay/create`
> 会失败（微信报 `mch_id参数格式错误`，支付宝报 `Missing key encoding`）。
> 本文说明接入真实支付需要配置什么。代码侧已就绪：凭据全部走环境变量，发起失败
> 会返回可读错误（不再是 HTTP 500）。

## 一、整体流程与三个必备条件

```
顾客点单 → /pay/create 发起支付 → 跳到微信/支付宝收银台 → 顾客付款
   → 支付平台【异步回调】 /pay/notify(微信) 或 /pay/alipay/notify(支付宝)
   → 后端校验签名+金额 → orderService.paid → 订单变"已支付"
```

要跑通，**三个条件缺一不可**：
1. **真实商户凭据**（微信商户号/密钥、支付宝 appId/私钥/公钥）。
2. **公网可达的回调地址**（`notifyUrl`）——支付平台的服务器在公网，**回调不到 `localhost`**。
   这是"付了钱但订单还是未支付"的头号原因。
3. **微信支付方式与 openid 流程对齐**（见第四节，需先拍板）。

## 二、需要设置的环境变量

`prod` profile 已全部改为读环境变量（`local` 仍用 test 占位，方便本地开发）。
部署生产时设置：

### 微信支付
| 环境变量 | 含义 | 从哪拿 |
|---|---|---|
| `WECHAT_MP_APPID` | 公众号 appId（JSAPI 支付用） | 微信公众平台 |
| `WECHAT_MP_APPSECRET` | 公众号 secret | 微信公众平台 |
| `WECHAT_MCH_ID` | 商户号 | 微信商户平台(pay.weixin.qq.com) |
| `WECHAT_MCH_KEY` | 商户 API 密钥(v2) | 微信商户平台 → API安全 |
| `WECHAT_NOTIFY_URL` | 异步回调，**公网**：`https://你的域名/sell/pay/notify` | 自己的域名 |
| `WECHAT_TPL_ORDER_STATUS` | 订单状态模板消息 ID（可选） | 公众平台 |

### 支付宝
| 环境变量 | 含义 |
|---|---|
| `ALIPAY_APP_ID` | 支付宝应用 appId |
| `ALIPAY_PRIVATE_KEY` | 商户私钥（PKCS8，一行，无 BEGIN/END） |
| `ALIPAY_PUBLIC_KEY` | 支付宝公钥 |
| `ALIPAY_NOTIFY_URL` | 异步回调，**公网**：`https://你的域名/sell/pay/alipay/notify` |
| `ALIPAY_RETURN_URL` | 同步跳回：`https://你的H5域名/order/status` |
| `ALIPAY_SANDBOX` | `true`=沙箱(不花钱)，生产设 `false` |

### 站点地址
| 环境变量 | 含义 |
|---|---|
| `PROJECT_URL` | 后端公网根地址（微信授权/回跳用），如 `https://你的域名` |

## 三、本地/测试怎么验证（沙箱）

本地 `localhost` 收不到回调，需要一条**公网隧道**把回调暴露出去：
```bash
# 任选其一，把本地 8080 暴露成公网 https 地址
cloudflared tunnel --url http://localhost:8080
# 然后把 WECHAT_NOTIFY_URL / ALIPAY_NOTIFY_URL 设成隧道给的 https 地址 + /sell/pay/...
```
- **支付宝**有完整沙箱：open.alipay.com → 沙箱，拿测试 appId/密钥/买家账号，设 `ALIPAY_SANDBOX=true`。
- **微信支付没有真正的沙箱**，需用真实商户号的小额测试。

## 四、点餐入口已定：微信扫桌码点餐（JSAPI）

入口拍板为「顾客在微信里扫桌上的码点餐」，链路按公众号内 **JSAPI** 支付落地，代码已改对：

- **#5 支付方式已对齐**：后端 `PayServiceImpl.create` 由 `WXPAY_MWEB` 改为 **`WXPAY_MP`**
  （best-pay-sdk 里的公众号 JSAPI 支付，返回 `appId/timeStamp/nonceStr/package/paySign`），
  与前端 `WeixinJSBridge.getBrandWCPayRequest` 对齐。
- **#4 openid 已改真**：前端 `order-page` 不再写死 `guest_<时间戳>`，改为从 URL `?openid=` 读取
  网页授权后回带的真实 openid（存 `sessionStorage.wx_openid`，下单/支付复用）；拿不到才退回 guest
  （仅供普通浏览器浏览/线下收银，微信在线支付不可用）。

### 一码两扫（顾客用哪个 App 扫，就用哪个钱包付）

微信内置浏览器屏蔽支付宝、反之亦然，无法在一个 App 里同时用两种在线支付。所以做成「一码两扫」：
**同一张桌码**指向中立的 H5 点餐页（如 `https://你的H5域名/order?table=5`），点餐页按所在环境自动分流：

- **微信扫进来**（UA 含 `MicroMessenger`）：点餐页自动先跳 `…/sell/wechat/authorize` 做
  `snsapi_base` 网页授权拿真实 openid（一会话只跳一次），回来后下单成功页**只显示微信支付**（JSAPI）。
- **支付宝扫进来**（UA 含 `AlipayClient`）：不需 openid，直接进；成功页**只显示支付宝**（WAP，支付宝内原生唤起）。
- **普通浏览器**：两个都显示，点哪个跳哪个。

顾客想换支付方式 = 用另一个 App 扫同一张桌码。前端已实现环境识别与分流（`order-page` 的
`detectPayEnv` + 成功页按环境显示），无需为两种支付各印一张码。

**还需做（部署侧，凭据/域名是你的）：**
1. **公众号网页授权域名**：把你的 H5 域名配进微信公众平台「网页授权域名」（`/sell/wechat/authorize` 后端已就绪）。
2. **真实商户凭据 + 公网 HTTPS 回调**：见第二节环境变量（`WECHAT_MP_APPID/SECRET`、`WECHAT_MCH_ID/KEY`、
   `WECHAT_NOTIFY_URL`、`ALIPAY_*`、`PROJECT_URL` 等）。

**验证边界（诚实说明）**：
- 代码侧已验到凭据这一步——本地 `test` 占位调 `/pay/create` 返回可读错误 `mch_id参数格式错误`
  （说明 JSAPI 链路已通、只差真实凭据）；前端环境分流逻辑随构建通过，普通浏览器默认路径（两个都显示、不跳转）本地可见。
- **微信/支付宝 App 内**的实际行为（授权回跳、JSAPI/WAP 唤起、真实小额扣款）属于外部环境，
  本地无法模拟，需你配好公众号/商户号/公网域名后，**分别用微信和支付宝扫码各付一单 0.01 验证**。

## 五、代码侧已做的改动（与本次排查相关）
- `prod.yml`：微信凭据/回调/站点地址全部改为环境变量（原来硬编码 `test`，运维设了变量也不生效）。
